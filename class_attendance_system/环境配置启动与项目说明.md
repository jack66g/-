# 课堂考勤系统 - 环境配置、启动与项目说明

## 一、项目简介

基于 **人脸识别** 的课堂考勤管理系统，支持学生刷脸签到、请假审批、管理员账号运维以及教师数据大盘。

| 层级 | 技术栈 | 说明 |
|------|--------|------|
| 后端 | Django 5.2.13 + DRF + OpenCV | RESTful API，SQLite 数据库，人脸识别引擎 |
| 前端 | Vue 3 + Vite 8 + Element Plus + Vue Router | SPA 单页面应用，响应式 UI |

## 四、后端启动

### 4.1 激活虚拟环境

```bash
cd backend

# Windows (Git Bash / CMD)
source venv/Scripts/activate

# 或者直接使用 venv 内的 Python（无需激活）
./venv/Scripts/python manage.py runserver
```

### 4.2 安装依赖（首次/新增依赖时执行）

```bash
# 确保在 backend/ 目录，且已激活虚拟环境
pip install -r requirements.txt
```

> **注意：** `requirements.txt` 包含大量 AI/ML 依赖（PyTorch、TensorFlow、OpenCV 等），完整安装可能需要数 GB 磁盘空间。如果只运行考勤核心功能，只需：`django`, `djangorestframework`, `django-cors-headers`, `numpy`, `opencv-contrib-python`。

### 4.3 数据库迁移（首次运行）

```bash
python manage.py makemigrations api
python manage.py migrate
```

### 4.4 创建超级管理员

```bash
python manage.py createsuperuser
```

### 4.5 启动开发服务器

```bash
python manage.py runserver 0.0.0.0:8000
```

后端启动后访问：**http://localhost:8000**

## 七、API 接口一览

所有接口前缀：`http://localhost:8000/api/`

| 方法 | 路径 | 说明 | 角色 |
|------|------|------|------|
| POST | `/api/login/` | 用户登录，返回角色信息 | 所有人 |
| POST | `/api/recognize/` | 上传照片进行人脸识别签到 | 学生 |
| GET | `/api/attendance/` | 获取考勤流水记录 | 教师/管理员 |
| GET | `/api/leaves/` | 查看请假列表 | 教师/管理员 |
| POST | `/api/leaves/` | 提交请假申请 | 学生 |
| PUT | `/api/leaves/` | 审批请假（通过/拒绝） | 教师 |
| POST | `/api/face/register/` | 录入学生人脸照片并训练模型 | 管理员 |
| GET | `/api/admin/users/` | 查看所有用户列表 | 管理员 |
| POST | `/api/admin/users/` | 创建新用户（学生/教师） | 管理员 |
| DELETE | `/api/admin/users/` | 删除用户 | 管理员 |
| GET | `/api/stats/` | 今日考勤统计数据大盘 | 教师 |

## 八、前端页面与角色流程

| 页面 | 路由 | 角色 | 功能 |
|------|------|------|------|
| 登录 | `/login` | 所有人 | 输入账号密码，根据角色跳转不同首页 |
| 学生首页 | `/dashboard` | 学生 | 查看个人信息、快捷入口 |
| 刷脸签到 | `/camera` | 学生 | 调用摄像头拍照，发送到后端识别签到 |
| 请假申请 | `/leave` | 学生 | 提交请假理由，查看审批状态 |
| 人脸录入 | `/register` | 管理员 | 为学生录入人脸照片，自动训练模型 |
| 管理员面板 | `/admin` | 管理员 | 创建/删除用户（学生和教师账号） |
| 数据大盘 | `/teacher-stats` | 教师 | 查看今日出勤/请假/缺勤统计 |

### 角色权限体系

```
登录 → 后端判定角色:
  ├── superuser  → admin   → /admin, /register
  ├── is_staff   → teacher → /teacher-stats
  └── 普通用户   → student → /dashboard, /camera, /leave
```

## 九、数据模型

### Student（学生）
| 字段 | 类型 | 说明 |
|------|------|------|
| user | OneToOne(User) | 关联 Django 内置用户 |
| student_no | CharField(20) | 学号，唯一 |
| class_name | CharField(50) | 班级名称 |

### Attendance（考勤记录）
| 字段 | 类型 | 说明 |
|------|------|------|
| student | ForeignKey(Student) | 关联学生 |
| check_in_time | DateTimeField | 签到时间（自动记录） |
| status | ChoiceField | present / late / absent |

### Leave（请假记录）
| 字段 | 类型 | 说明 |
|------|------|------|
| student | ForeignKey(Student) | 关联学生 |
| reason | TextField | 请假理由 |
| status | ChoiceField | pending / approved / rejected |
| apply_time | DateTimeField | 申请时间（自动记录） |

## 十、人脸识别流程

```
录入阶段：
  管理员拍照 → 前端发送多张 Base64 照片
  → 后端保存到 api/dataset/{student_id}/
  → 自动调用 OpenCV LBPH 训练 → 更新 trainer.yml

签到阶段：
  学生拍照 → 前端发送单张 Base64 照片
  → 后端解码 → LBPH 识别 → 匹配 student_id
  → 防重复检查 → 写入 Attendance 表 → 返回结果
```

## 十二、常见问题

### Q: 启动后端报 `ModuleNotFoundError`
A: 确保已激活 venv 并安装依赖：`pip install django djangorestframework django-cors-headers numpy opencv-contrib-python`

### Q: 前端访问后端跨域报错
A: 已在 `core/settings.py` 中配置 CORS 白名单 `localhost:5173`。若前端端口变化，需更新 `CORS_ALLOWED_ORIGINS`。

### Q: 人脸识别报错找不到 `trainer.yml`
A: 需要先通过 `/api/face/register/` 为至少一个学生录入人脸照片，系统会自动训练生成模型文件。

### Q: 数据库文件丢失怎么办
A: 删除 `db.sqlite3`，重新执行 `python manage.py migrate` 后会重建空数据库，然后需要用 `createsuperuser` 重新创建管理员账号。
